Tagteam

for Reveal.js

.../demo.html?t=tagteam

What is it?

Tagteam is used to dynamically show only certain sections in presentations when you don’t want to show everything. It uses URL parameters to do that.

The bar along the top is Simplemenu, loaded here on purpose: it is the quickest way to see a chapter added or removed.

With Tagteam you can:

  • Show only sections with certain tags
  • Show only sections with certain names
  • Show predefined groups of sections
  • Hide a set of sections until the URL asks for them
  • Reveal a hidden section without touching the rest
  • Combine these methods for flexible control

Tagteam reads 3 different URL parameters:

  1. ?t=abcd for data-tag sections
  2. ?n=abcd for data-name sections
  3. ?g=abcd for predefined groups

Tagteam only looks at the sections you have marked. One with neither a data-tag nor a data-name is left alone.

When a parameter filters, the marked sections it does not name are hidden. With no parameter at all nothing is filtered, so the deck you wrote is the deck you get.

Sections you list in hide work the other way round.

An ordinary tagged section is already hidden by a parameter that does not name it. hide changes two things: it starts hidden even with no parameter at all, and naming it does not filter the rest of the deck the way naming an ordinary tag would.

In "unhide" mode neither is special. Nothing filters there to begin with, so this is simply how the mode works.

Two ways to use it

mode What a URL parameter does
"select" Picks what is shown, and hides every other marked section
"unhide" Shows what it names, and leaves everything else alone

"select" is the default. With no parameter at all neither mode filters anything, so the deck is what you wrote, less whatever it holds out.

Always shown

A section with data-tag="keep", like the title slide of this presentation, is left out of both filters and is always shown, except when a group is mandatory.

It only matters in "select" mode, and only for a section that also has a data-tag or a data-name. An unmarked section is already always shown, and in "unhide" mode no parameter ever hides an ordinary marked one.

keep has to be the whole attribute value. data-tag="keep, intro" is an ordinary tagged section, and is filtered like any other.

Setup

Set up your HTML with data-tags and/or data-names:

<section data-name="Brown" data-tag="nice">
    <section data-tag="cats, small">Cat (brown, small, nice)</section>
    <section data-tag="dogs">Dog (brown, nice)</section>
    <section data-tag="dogs, big">Dog (brown, big, nice)</section>
    <section data-tag="horses">Horse (brown, nice)</section>
</section>
<section data-name="Black &amp; white">
    <section data-tag="cats">Cat (black &amp; white)</section>
    <section data-tag="dogs, small">Dog (black &amp; white, small)</section>
    <section data-tag="horses">Horse (black &amp; white)</section>
</section>

The above markup is used in all following examples.

Note: data-tag can hold several comma-separated tags. data-name holds a single name, which may be several words long.

JavaScript

Load the script and make a reference to it in the Reveal plugin options.

<script src="plugin/tagteam/tagteam.js"></script>
<script>
    Reveal.initialize({
        plugins: [ Tagteam ]
    });
</script>

When using the Markdown plugin as well, load it first, so Tagteam can find the tagged or named sections it writes.

Choose a mode

mode says how the deck behaves. This demo does not set it, so Tags, Names and Groups below all run on the default, "select": a parameter picks what is shown and hides every other marked section.

Reveal.initialize({
    //...
    tagteam: {
        mode: "select"
    },
    plugins: [ Tagteam ]
});

"unhide" is the other mode: nothing is hidden by a parameter, only shown. See the select demo and the unhide demo for a full deck built around each.

Using more specific t parameters

Use the plus sign to be more specific.
In this case we want all dogs, but only small cats.

.../demo.html?t=dogs,cats+small

Test it here now: demo.html?t=dogs,cats+small

Using more specific t parameters

This works with inherited tags as well: a vertical slide also counts the tags on its stack.

.../demo.html?t=small+cats,nice+horses

Test it here now: demo.html?t=small+cats,nice+horses

Tags work the same in both modes

Here, in "select", ?t=dogs shows the dogs and hides everything else that is tagged.

In "unhide", the same ?t=dogs would only reveal a dogs section that hide had marked. Nothing else would move.

Names

When ordering your presentation with nested sections, you can specify these to be shown in one fell swoop.

Using an n parameter

There are two named stacks with vertical slides. Now we only want the first (data-name="Brown") stack.

.../demo.html?n=brown

Test it here now: demo.html?n=brown

Using multiple n parameters

.../demo.html?n=brown,black+%26+white

Test it here now: demo.html?n=brown,black+%26+white

Combining names and tags

Only black & white horses, and small black & white dogs.

.../demo.html?n=black+%26+white&t=horses,small+dogs

Test it here now: demo.html?n=black+%26+white&t=horses,small+dogs

Names work the same in both modes

Here, in "select", ?n=brown shows that chapter and hides every other chapter that has a name.

In "unhide", the same ?n=brown would only reveal a chapter named Brown that hide had marked. Nothing else would move.

Groups

Groups are predefined sets of tags and/or names.

Setting a groups option

Each group needs a name, and an array of tags and/or an array of names.

Reveal.initialize({
    //...
    tagteam: {
        groups: {
            "brownpets": {
                names: ["brown"], tags: ["cats", "dogs"]
            },
            "bwhsd": {
                names: ["black & white"], tags: [ "horses", ["dogs", "small"] ]
            }
        }
    },
    plugins: [ Tagteam ]
});

Note: in the 2nd group, the tags contain a nested array to be more specific (small dogs only).

Using a g parameter

.../demo.html?g=brownpets

Test it here now: demo.html?g=brownpets

Setting the mandatorygroup option

It is possible to make the use of a group mandatory. This way you avoid the possibility for users to see all slides by just not entering any URL parameter.

Reveal.initialize({
    //...
    tagteam: {
        mandatorygroup: true,
        groups: {
            "brownpets": {
                names: ["brown"], tags: ["cats", "dogs"]
            }
        }
    },
    plugins: [ Tagteam ]
});

Note: this is just a simple safeguard. Anyone with a bit of HTML knowledge can find the valid group names.

Using a correct g parameter

With mandatorygroup: true and a correct g parameter, the slides will show.

.../demo-mandatory.html?g=brownpets

Test it here now: demo-mandatory.html?g=brownpets

Using an incorrect g parameter

With mandatorygroup: true and an incorrect g parameter, the slides will NOT show. Only slides with data-mandatory will be shown.

.../demo-mandatory.html?g=pinkpets

Test it here now: demo-mandatory.html?g=pinkpets

Groups work the same in both modes

A group just resolves into tags and names, so it behaves exactly like they do. Here, in "select", ?g=brownpets picks what is shown and hides the rest.

In "unhide", the same group would only reveal whatever of it hide had marked. Nothing else would move.
